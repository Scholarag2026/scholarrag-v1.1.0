## Screening of candidates

Pass 1 kept a work when: the title contains 'feedback'; the title or abstract contains 'writ'; `best_oa_location.pdf_url` is present; the journal is not Frontiers in Psychology (excluded to keep the set within applied-linguistics venues). 44 candidates.

Pass 2 (after the backend-client re-check below left only 10 usable papers) re-screened the remaining raw works with a purely lexical rule: the title mentions feedback, error correction or revision, `best_oa_location.pdf_url` is present and the journal is not Frontiers in Psychology. Topical fit with the written-feedback protocol was not judged at this stage but at selection time (see 'Verified but not selected'). 7 candidates were added: 10.1016/j.asw.2021.100586, 10.1016/j.asw.2018.11.001, 10.1007/s11145-023-10466-8, 10.1017/s0261444824000478, 10.1016/j.asw.2019.05.001, 10.1111/lang.12719, 10.1080/09658416.2025.2585004. 51 candidates in total (`candidates_filtered.json`, field `screening_pass`).

## Open-access verification

Route (`verify_pdf.py`): Unpaywall `GET https://api.unpaywall.org/v2/<doi>?email=<UNPAYWALL_EMAIL>` (the address is read from the environment or the repository `.env`; it is not stored in the package). Only `best_oa_location.url_for_pdf` is used; when Unpaywall returns no PDF URL the script falls back to the single OpenAlex `best_oa_location.pdf_url` carried in the candidate record. No other `oa_locations` are tried.

The PDF check uses a client equivalent to the backend's `fetch_pdf_from_url` (`backend/app/services/fulltext.py`): `httpx.Client(timeout=30.0, follow_redirects=True)` with httpx's default User-Agent and no extra headers. A URL passes when the response is HTTP 200 with `content-type: application/pdf` and a body beginning with `%PDF`. This is what the product itself observes during full-text acquisition, so `pdf_http_status` and `pdf_content_type` in `seed_dois.json` describe the pathway the demo reproduces. (An earlier verification pass used a Chrome-like User-Agent, which the backend does not send.)

Result: 14 of 51 passed the PDF check; 37 were rejected. All 14 passing papers were found through Unpaywall (`oa_verified_via` = `unpaywall`). With `--browser-ua` the script also records what a browser User-Agent would get: 13 candidates (all hosted on scholarspace.manoa.hawaii.edu, Language Learning & Technology) return a PDF only to a browser User-Agent and HTTP 403 to the backend client; they are rejected and none of them is a seed.

## Claim construction

Source paper: Mao, Z., Lee, I., & Li, S. (2024). Written corrective feedback in second language writing: A synthesis of naturalistic classroom studies. *Language Teaching*, 57(1). https://doi.org/10.1017/S0261444823000393 - published version (CC BY) from the Cambridge Core PDF recorded in `seed_dois.json`, text extracted with `pymupdf` (the library the backend uses). The paper was chosen because the backend claim extractor only parses citations of the form `(Surname, YEAR)` / `(Surname et al., YEAR)` with a single ASCII capitalised surname and keys papers as `surname_year` from the first author's last-name token; `Mao` + `2024` gives `mao_2024`, which no other seed shares. Both claims are built from the abstract sentence quoted in `protocol.json` -> `claims[].construction` ("A systematic search generated 50 empirical studies ... four major themes ...") together with the abstract's description of the corpus as naturalistic studies in which feedback is not manipulated: `supported-1` paraphrases them; `unsupported-1` reverses the study design (experimental, manipulated feedback) and the number of themes (two).

The previous claim source (Bonilla López et al., 2018, 10.1111/lang.12295) stays in the library as a seed but is not cited by a claim: its first-author key is `lópez_2018`, which the backend regex cannot produce from any ASCII citation.

## Files in demo/tools/

`verify_pdf.py` is the verification script (`python demo/tools/verify_pdf.py candidates_filtered.json verified.json --browser-ua`); it prints the counts used above. `build_sources.py` regenerates this file. `sources.json`, `candidates_raw.json`, `candidates_filtered.json`, `verified.json`, `selected.json` are the inputs/outputs kept for audit. The downloaded PDF and its text are not committed.
